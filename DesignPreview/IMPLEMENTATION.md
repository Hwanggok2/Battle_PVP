## 화면 및 직접 확인 방법

- 첫 화면은 **BATTLE PVP**만 표시한다. 오른쪽 아래 `◫`는 시안 화면 선택 도구이며 실제 게임 UI에 포함하지 않는다.
- 로비: 전투 참가, 스탯 설정, 캐릭터, 설정. 배경은 작전실 3D 공간이다.
- 방 목록에서 입장하면 그 방의 기존 인원 + 본인만큼 출격 격납고에 표시한다. 새 방은 본인 1명으로 시작한다. 대기실 바로보기는 8인 배치를 보여준다.
- 대기실 아래 **1명 입장/1명 퇴장/방장으로 보기**는 통신을 흉내 내는 검토 도구다. 실제 참가자에게 메시지를 보내지 않는다.
- 맵 둘러보기: 네 공간 선택, 카메라 회전/확대/초기화, 평면/근접 보기, 바닥·하늘 ON/OFF. 바닥 원본과 3D 맵 구조를 저장할 수 있다.
- 전투: Q/E 또는 스킬 버튼을 눌러 사용한다. 전략가 E는 다음 프리셋, 폴리매스 E는 검/활 전환이다. 모노스탯에는 E 슬롯이 없다. 시안 하단 직업 선택으로 6가지 구성을 확인한다.
- 설정의 조작 탭에서 스킬 키를 바꾼다. 중복/이동/채팅/메뉴 키는 거부한다. 적용한 설정만 이 브라우저의 localStorage에 저장한다. 계정·프로필은 저장하지 않는다.
- 사운드: 기존 Lobby.mp3를 실제 재생한다. 전체/BGM/UI 음량, 음소거를 적용한다. UI 클릭은 90ms의 저음 전자 펄스 WAV를 사용하며, 스킬 효과음은 임시 확인음이다. 브라우저 정책상 클릭 이후에만 소리를 재생한다.
- 시스템: 품질은 렌더 해상도/그림자, 밝기는 노출, 최대 프레임은 렌더 주기, HUD 크기·투명도는 HUD, 움직임 줄이기는 자동 카메라 회전에 연결한다. 전체화면은 브라우저가 지원하는 경우에만 동작한다.
- 전투의 Enter/T로 채팅을 열고 Escape로 입력을 빠져나온다. 설정창/채팅 입력 중에는 Q/E가 발동하지 않는다. 화면 클릭/터치 또는 우측 공격 버튼으로 사각 잔상을 확인한다. Space/앉기/피해/명중의 물리 동작은 구현하지 않았다.

`CombatSkillRules.TrySelect`와 `Assets/Player/skill`의 `JobSkillData`를 기준으로 한다. HTML 표시 수치는 실제 게임 에셋의 현재 값이다.

| 모노스탯 힘 | 광폭 · 40초 | 없음 |
| 모노스탯 체력 | 발차기 · 10초 | 없음 |

폴리매스용 옛 프리셋 스킬 에셋은 존재하지만 현재 규칙에서 허용하지 않으므로 시안 슬롯에도 넣지 않았다. 모노스탯의 공격·상태 효과는 HTML에서 실제 피해를 발생시키지 않는다. 서버 판정과 밸런스 검증은 이 시안의 범위가 아니다.

## 3D 맵과 Unity 이식 자료

| 공간 | 크기 | 역할/재료 |
|---|---|---|
| 작전실 | 28 × 24 m | 금속 패널, 장비 랙, 제어 콘솔, 도시 전망창. 로컬 플레이어 중심 로비 |
| 출격 격납고 | 24 × 20 m | 금속 패널, 참가자 8명, 중앙 집결 구역, 격납고 문. 전용 대기실 |
| 연구 구역 | 36 × 32 m | 금속 패널, 네 격리 장비, 중앙 교전, 양측 정비 통로. Battle 디자인 A |
| 네온 옥상 | 36 × 32 m | 콘크리트 바닥, 환기 장치, 교차 엄폐벽, 도시 야경. Battle 디자인 B |

- 맵은 배경 그림이 아니라 Three.js의 메시·재질·조명으로 렌더링한다. 바닥 PNG가 Plane UV에서 반복되고 하늘 PNG가 EquirectangularReflectionMapping 배경에 연결되어 있다.
- 바닥 텍스처 1회 반복은 5 × 5 m를 기준으로 한다. 3D에서는 Unity의 2D Tilemap보다 **Grid 좌표 + 공유 메시/머티리얼을 사용하는 모듈형 바닥**이 이 구조와 맞는다. 경계·단차를 바닥 모듈로 나누되 드로우콜은 배칭/인스턴싱으로 묶는다.
- `assets/maps/*.glb`는 화면과 같은 맵 생성 코드에서 추출한 구조 메시다. **텍스처·하늘·충돌체·네트워크는 GLB에 포함되지 않는다.** glTF 임포터가 있는 도구에서 열 수 있으며 Unity 도입 시 프로젝트의 임포트 경로를 확정해야 한다.
- `assets/maps/map-layouts.json`에 Y-up, 미터 단위, 맵 크기, 바닥 이미지, 반복 수, 하늘 이미지, 스폰 후보 좌표를 기록했다. GLB의 `Floor_Alloy`/`Floor_Concrete`에 해당 이미지를 연결한다.
- 금속/콘크리트 PNG는 알베도만 제공한다. Unity에서 sRGB, Repeat, mipmap, 플랫폼별 크기/압축을 설정하고 경계 이음매를 실제 반복면에서 확인한다. 노멀/러프니스 맵이 제작된 것으로 간주하지 않는다.
- 하늘은 1774 × 887의 2:1 파노라마다. Unity의 선택된 렌더 파이프라인에 맞는 스카이 머티리얼에 연결한다. 브라우저와 Unity의 노출·톤매핑은 동일하지 않으므로 그대로 일치한다고 보장하지 않는다.
- 캐릭터는 프로젝트의 `Ch10_nonPBR.fbx`와 `Move/Idle.fbx`를 사용해 0.6초 대기 자세를 정적 GLB로 추출했다. 브라우저 용량을 위해 원래 대형 FBX를 배포하지 않는다. 구분용 단색 머티리얼이며 원본 캐릭터 텍스처/스켈레탈 애니메이션은 아직 연결하지 않았다.
- HTML 전투 카메라는 현재 Unity의 몸 일부가 보이는 근접 시점을 기준으로 한다. 맵 둘러보기/로비/대기실 배치 화면은 공간 검토용 외부 시점이다. 실제 FollowCamera의 전체 동작, 충돌, 피격 판정, 엄폐 판정 또는 Unity 성능 측정 결과가 아니다. Battle 두 맵은 디자인 후보이며 기존 프로젝트에 새 게임 모드를 추가하지 않았다.

## Unity 연결 지점과 적용 순서

1. 승인된 맵부터 Login/Lobby/Battle_waiting/Battle에 적용. 기존 네트워크 플레이어 프리팹·씬 전환 수명은 유지. 대기실 전용 스폰 위치와 8명 수용 공간을 구성한다.
2. `PlayerInputActions.inputactions`에 Skill1/Skill2를 추가하고 생성 C#을 갱신한다. `PlayerCombat`의 현재 scroll→SelectSkill/rightButton→UseSkill 흐름을 직접 슬롯 요청으로 변경한다. 서버의 `CombatSkillRules` 권한 검사는 유지한다.
3. `SkillHudPresenter`/`SkillUI`를 슬롯별 표시로 연결한다. 재바인딩과 직업/프리셋 변경 시 키, 아이콘, 쿨다운이 일치해야 한다. 사망·모달·채팅 상태에서 입력 누수가 없어야 한다.
4. 현재 `BgmManager`/`BgmSettings`를 확인하고 전체/BGM/SFX/UI 채널을 AudioMixer에 연결한다. 기존 BGM 흐름을 중복 재생하지 않는다. 그래픽/조작/음량 설정은 서버 프로필과 분리된 장치 로컬 설정으로 저장한다.
5. 설정·스탯·회원가입·확인·연결·사망·결과 패널의 초기 비활성과 포커스 복구를 검증한다. 로비 커서는 항상 보이고 전투 포인터 잠금은 기존 `GameInputController` 정책을 따른다.
6. 실제 8인 입·퇴장/호스트 종료/재접속, Windows/WebGL의 UI 확대와 성능, 타일 이음매·카메라·조명·스폰·충돌까지 확인한 뒤 Unity 리모델링 완료로 기록한다.

- 작전실 → 출격 격납고 → 연구 구역/네온 옥상의 공간 관계를 유지했다. 지도 ID는 기존 lobby/waiting/arena/foundry를 유지하여 방 선택 동작을 보존했다.
- 바닥 2종과 도시 야경 파노라마를 새로 생성하여 실제 3D UV/배경에 연결했다. 과도한 화면 글리치, 깜빡임, 블룸은 추가하지 않았다.
- 시작 화면은 게임 제목만 유지했다. 대기실 인원 변경, 호스트 표시, Q/E 스킬, 시스템·사운드·조작 설정은 기존 흐름을 사용한다.
- GLB와 map-layouts.json도 현재 3D 구조에서 다시 추출했다. 이 단계는 HTML 확인용이며 Unity 씬·프리팹·실제 입력은 변경하지 않았다.
- 바닥은 타일 반복으로 확인하지만 픽셀 단위 무봉제 및 Unity 렌더링 일치는 보장하지 않는다. 승인 후 Unity 조명·재질·콜라이더·8인 성능을 확인한다.

## UI 효과음과 전투 시점 (2026-09-25, v4)

- 사용자 확인: 현재 Unity에서 캐릭터 일부가 보이도록 한 카메라는 의도한 설정이다. 1m 뒤 오프셋은 수정 대상 버그가 아니며 Unity 카메라/씬/StatManager는 변경하지 않는다.
- HTML 전투 화면의 원거리 조감 카메라를 근접 추적 카메라로 교체했다. `FollowCamera` 피벗 높이 1.5m + `StatManager` 기본 오프셋 (0.3, 0.2, -1), STR/CON 모노스탯 오프셋 (0.35, 0.4, -1), Battle 씬 FOV 60도를 참고한다. 좌표계에 맞춰 Three.js 방향으로 변환했다.
- 캐릭터는 원본 약 1.75m 비율로 표시하고 STR/CON 모노스탯은 1.2배를 적용한다. 로컬 본체를 숨기지 않는다. 정적 Idle 메시이므로 실제 몸/무기/애니메이션의 보이는 범위가 완전히 같지는 않다.
- 전투에서는 드래그로 시점을 바꾸고 WASD/터치 화살표로 시점 방향에 맞춰 이동한다. 휠/핀치로 외부 시점이 되지 않는다. 모달은 시점 입력을 막는다. 맵 둘러보기는 기존 궤도 카메라를 유지한다.
- `assets/audio/ui-terminal-click.wav`: 44.1kHz/16bit/mono/90ms, 자체 합성한 저음 하강 펄스와 짧은 필터 노이즈. 상승하는 밝은 비프음을 제거했다. UI/전체 음량·음소거·백그라운드 음소거를 적용하며 연속 입력 시 중첩을 제한한다.

## 사각 공격 효과와 원호 스킬 HUD (2026-09-25, v5)

- 사용자 요청의 사각형 공격 잔상을 바탕으로 직접 구성했다. 검 공격에는 사각형 궤적 20개와 파편 16개, 청록색 외곽 발광, 주변에 비치는 180ms 점광원을 사용한다. 사각 조각은 순차적으로 나타나고 총 460ms 안에 사라진다. 활 상태는 좁은 전방 발광으로 표시한다.
- `combat-effects.js`의 재사용 가능한 InstancedMesh 두 개(중심/외곽), 공유 BoxGeometry 한 개, PointLight 한 개로 구성한다. 매 클릭마다 메시를 생성하지 않으며 입자 수는 36개로 고정이다. 240ms 입력 간격은 HTML 연출용 제한이며 실제 Unity 무기 공격속도를 바꾼 것이 아니다.
- 화면 짧은 클릭/터치는 공격, 8px 이상 드래그는 시점 이동으로 구분한다. 우측 공격 버튼으로도 재생된다. 설정/사망/채팅/스킬 시전 중 공격을 차단하고 화면/맵 전환 또는 모달을 열면 효과를 정리한다.
- Q/E는 우측 공격 버튼의 왼쪽 위 ¼원호에 배치한다. 스킬이 1개면 원호 중앙에 놓는다. 키 재지정·직업 변경·이름·쿨다운은 기존 상태에 연결하며 남은 시간을 원형 테두리로 표시한다.
- PC·휴대폰 세로·가로에 맞춰 원호와 버튼 크기를 조정한다. 가로 화면에서는 투명한 체력 HUD 컨테이너가 공격 버튼을 가리지 않도록 입력 영역을 분리했다.
- Unity 카메라/스킬/전투 판정에는 변경이 없다. 현재 공격은 외형 확인용이며 무기 애니메이션·피해 판정·명중 이펙트는 구현하지 않았다. 승인 후 실제 공격 애니메이션 타이밍, 서버 판정, 풀링/플랫폼 성능에 연결한다.

## 맵의 다색 네온 조명 (2026-09-25, v6)

- 사용자 요청은 맵 조명에 적용했다. 작전실 CITY LINK/OPS, 격납고 HANGAR/ARMORY, 연구 구역 SECTOR/LAB, 옥상 ROOF/NIGHT LINE 및 주변 건물 NOVA/PULSE에 청록·마젠타·보라·앰버 간판을 배치했다. 시야를 가리는 중앙 구조물은 추가하지 않았다.
- 간판은 3D 판넬과 발광 문자 메시다. 기능성 픽셀 문자를 간판당 하나의 메시로 병합했으며 별도 이미지·폰트 다운로드가 필요 없다. 주변 장비/바닥에 실제 점광원으로 색을 비추고, 로컬 셰이더의 부드러운 발광을 더했다. 화면 전체 블룸이나 반복 점멸은 사용하지 않는다.
- 맵 점광원은 맵당 4개, 그림자 없음으로 제한한다. 낮음 품질에서는 이 점광원을 끄고 간판/발광 재질/약한 바닥 빛을 유지한다. 기본 조명 세기를 조정해 색을 살리되 중앙 전투 바닥은 낮은 채도로 유지했다. 이는 성능 설계이며 실제 Unity 8인 60 FPS 측정 결과는 아니다.
- `map-neon.js`로 간판·조명 구성을 분리했다. 맵 교체 시 기존 world의 메시/재질 정리와 함께 제거되며 품질 설정도 다음 맵에 유지된다. 기존 공격 효과, HUD 배치, 근접 전투 카메라는 유지한다.
- 네 맵 GLB를 재생성했다. 간판 문자/판넬, unlit 색상 재질, KHR_lights_punctual 점광원은 포함하며 브라우저 전용 부드러운 halo 셰이더는 제외한다. `map-layouts.json`에 간판 문구·위치·색, 조명 위치·색·세기를 기록했다. Unity에서는 렌더 파이프라인에 맞게 발광/빛 번짐과 조도를 조정해야 한다.
- PC 1440×900의 네 맵, 전투 근접 시점, 휴대폰 390×844, 낮음↔보통 품질 전환을 브라우저에서 확인했다. 기둥이 간판 글자를 가리던 배치를 보정했다. HTML 미리보기 변경이며 Unity 씬에는 아직 적용하지 않았다.
