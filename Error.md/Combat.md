# Combat Errors

## WebGL 클라이언트에서 한 번의 공격에 데미지 팝업이 두 번 표시됨

### 증상
- 클라이언트가 한 번 공격했는데 공격자 화면에 데미지 팝업이 두 개 표시될 수 있다.
- 호스트가 잃는 체력은 한 번의 공격분이므로 서버 데미지는 중복 적용되지 않는다.
- 네트워크 지연이 커질 때 재현 빈도가 증가한다.

### 원인
- 클라이언트는 입력 지연을 감추기 위해 로컬 충돌 시 예측 데미지 팝업을 즉시 표시한다.
- 서버가 타격을 확정하면 모든 클라이언트에 확정 데미지 팝업 RPC를 전송한다.
- 기존 구현은 피해자별 예측 팝업 개수와 5초 만료 시간만으로 확정 팝업을 억제했다.
- 확정 RPC가 5초 뒤 도착하거나 확정과 예측의 도착 순서가 바뀌면 같은 공격인지 정확히 구분할 수 없었다.
- 서버 자체 히트박스가 클라이언트의 `CmdReportMeleeHit`보다 먼저 타격을 처리하면 팝업 예측 ID가 전달되지 않았다. 이 경우 서버의 타격 대상 중복 검사는 실제 데미지를 한 번만 적용하지만, 공격자 클라이언트에는 예측 팝업과 확정 팝업이 모두 표시됐다.

### 해결 방법
- 일반 공격은 기존 `attackSequence`, 활 공격은 네트워크 투사체의 `netId`를 팝업 예측 ID로 사용한다.
- 예측 및 확정 팝업을 `공격자 netId + 피해자 netId + 예측 ID`로 연결한다.
- 예측 또는 확정 중 먼저 도착한 팝업만 표시하고, 같은 ID로 다시 들어오는 모든 팝업을 생략한다.
- 서버 자체 근접 히트박스와 `CmdReportMeleeHit` 경로 모두 현재 공격 시퀀스를 전달한다.
- 표시 기록은 30초간 유지되며, 다음 팝업 처리 시 만료 기록을 정리해 이후 공격의 팝업을 가리지 않는다.

### 확인 방법
1. WebGL 클라이언트에서 호스트를 일반 공격으로 한 번 타격한다.
2. 공격자 클라이언트에 데미지 팝업이 한 번만 표시되는지 확인한다.
3. 호스트 체력이 한 번의 공격분만 감소하는지 확인한다.
4. 네트워크 지연이 발생한 상태에서도 같은 결과인지 확인한다.
5. 활 공격도 예측 팝업과 서버 확정 팝업이 겹치지 않는지 확인한다.
